## 🔍 问题模式分析

### 核心问题：换行符不匹配

**问题描述:**
- LLM生成的`old_text`使用`\n`（LF）
- Windows文件实际使用`\r\n`（CRLF）
- Coordinator的换行符规范化逻辑在某些场景下失效

**失败模式:**
```
❌ OLD TEXT NOT FOUND IN EVIDENCE!
First 100 chars of old_text: '    private void Start()\n    {\n...'
```

**影响任务:**
- A4, C1, C2, C3, D1, E1 (6个任务，42.9%)

**根本原因:**
1. **LLM输出规范化不足** - LLM生成multi-line old_text时使用`\n`
2. **Evidence读取正确** - 使用`read_bytes()`保留了`\r\n`
3. **规范化时机错误** - Coordinator在生成mutation后才规范化，而非在LLM输出时

### 次要问题：时间预算

**问题描述:**
- 任务B1执行成功但超时7秒（37.04s vs 30s预算）

**原因:**
- Explorer exploration消耗了额外时间
- 时间预算设置较紧（Simple任务30秒）

**影响范围:** 6个任务（42.9%）

**解决方案：**

**方案A: 在LLM输出后立即规范化**
```python
# coordinator.py - 在解析LLM响应后
for action in actions:
    if 'old_text' in action['arguments']:
        old_text = action['arguments']['old_text']
        # 规范化为evidence的换行符格式
        action['arguments']['old_text'] = normalize_to_evidence(old_text, evidence_sha)
```

**方案B: 在prompt中明确要求CRLF**
```python
prompt = f"""
Generate mutation with old_text using Windows line endings (\\r\\n).
File evidence SHA: {evidence_sha}
Ensure old_text exactly matches the evidence content including line endings.
"""
```

**方案C: ACI mutation层智能匹配**
```python
# mutation.py - 在matching时尝试所有换行符变体
variants = [
    old_text,                                    # As-is
    old_text.replace('\n', '\r\n'),             # LF → CRLF
    old_text.replace('\r\n', '\n'),             # CRLF → LF
]
for variant in variants:
    if variant in evidence_text:
        return apply_patch(variant, new_text)
```

**推荐：方案C** - 最健壮，不依赖LLM行为
